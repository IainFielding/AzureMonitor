# Workbook reference

One page per workbook: every tab and panel, what it reports, and where its data comes from. Generated from the workbooks by `src/build_docs.py`. For which workbook to use when, see the [main README](../README.md).

| Workbook | What it is for |
|---|---|
| [Enterprise Scale Platform Health](alz-platform-health.md) | Health, capacity and throughput of the shared platform: Virtual WAN connectivity (Firewall, ExpressRoute, VPN, end-to-end connectivity tests), application delivery, AI Foundry, shared services, identity, Azure VMware Solution, Azure Virtual Desktop, storage, build agents, governance, security, monitoring and backup. |
| [Platform availability](availability-report.md) | The availability of each shared platform service against a **Target%** target, the incidents behind it, and the Azure-wide incidents and maintenance that touched the estate. |
| [Azure Virtual Desktop disconnections and Azure Firewall](avd-firewall.md) | Do users drop off Azure Virtual Desktop when the firewall is short of SNAT ports, unhealthy, slow or scaling? The disconnections and the firewall's signals on the same timeline, and how strongly each signal lines up with them. |
| [Azure Virtual Desktop: one user's sessions](avd-user.md) | Why is this user's session failing, slow to start, or laggy? Their connections and how each ended, the errors and their likely cause, sign-in time by stage, network quality, and the health and load of the session hosts they used. |
| [Azure VMware Solution](avs.md) | Are the private clouds healthy, do they have room to grow, are they connected and monitored, and what are vCenter, ESXi and NSX reporting? |
| [Backup & Recovery](backup-recovery.md) | Is everything that should be backed up or replicated protected, is it working, and could it be restored? Azure Backup (Recovery Services and Backup vaults), Site Recovery, Azure SQL and SQL Server in VMs, and storage accounts. |
| [Azure Bastion](bastion.md) | Every Bastion host: how it is configured, whether its subnet is right, which VMs it can reach, the rules that let RDP and SSH round it, who connected to what, how busy it is, and who changed it. |
| [What changed?](changes.md) | Every change to the resources in scope over the time range: what changed, each property before and after, who changed it and with what tool, with the health transitions, alerts, Service Health events and access changes from the same window alongside. |
| [Cloud Center of Excellence](cloud-center-of-excellence.md) | One scorecard for the team that sets cloud standards: governance and tagging, landing zone placement, security posture and privileged access, savings and idle resources, monitoring, patching and retirements, by subscription. Read from Azure Resource Graph: no workspace needed. You need **Reader** across the subscriptions (at the tenant root management group to see everything). |
| [DNS and private endpoints](dns-troubleshoot.md) | Why does this name not resolve, or resolve to the wrong address? Follows a Private Link name from the endpoint to its private DNS zone, the networks the zone is linked to, and the DNS server the client uses, then shows what the DNS servers actually answered. |
| [DNS](dns.md) | DNS across the estate: Azure Firewall DNS proxy, private DNS zones and their links, DNS Private Resolvers, forwarding rulesets and DNS security policies, the DNS servers each VNet uses, and what the DNS servers are answering. To follow one name, use the **DNS and private endpoints** workbook. |
| [Expiry and renewals](expiry.md) | Everything with a date the platform team has to act on before it passes: certificates, Key Vault objects, storage keys, AVD registration tokens, policy exemptions, service retirements, planned maintenance, reservations and savings plans. |
| [FinOps hubs](finops-hubs.md) | Are the FinOps hubs healthy and up to date, are the Cost Management exports landing, are the Data Factory pipelines and triggers running, and is Azure Data Explorer ingesting and holding current data? Built for FinOps toolkit **v15**; works with earlier hubs. |
| [Firewalls: blocked connections](firewall-troubleshoot.md) | Is a firewall blocking this connection, and which rule did it? Covers Azure Firewall (network, application and DNAT rules, threat intelligence and IDPS), Palo Alto, Check Point and NSGs, and shows where along the path a flow stops. |
| [Azure Firewall](firewall.md) | Every Azure Firewall: how it is built and reaches the internet, how healthy and busy it is, why it runs short of SNAT ports and who is taking them, its policies, and the traffic it denies or flags. |
| [Log Analytics: cost and noise](log-cost.md) | Where is ingestion going, what does it cost, and what could you stop paying for? Volume by table and source, spikes, tables nobody queries, data collected twice, and the workspace's plan and limits. |
| [Azure Policy Compliance](policy-compliance.md) | Compliance, exemptions, regulatory frameworks, remediation and governance hygiene across the tenant, using **Azure Resource Graph**. Data is the latest evaluation result for each resource (Azure Policy re-evaluates about every 24 hours, and after a resource changes). |
| [Why was this request refused?](policy-denials.md) | Azure Policy denials and the other reasons Resource Manager refuses a request (permissions, locks, quota, template errors), and for a policy: which assignment, which policy, the values that failed it, and how to exempt or exclude. |
| [Privileged access](privileged-access.md) | Who holds and uses privileged access, and is it granted properly? PIM activations and the approvals behind them, assignments made outside PIM, risky application permissions, Azure access administrators, and how privileged and break-glass accounts sign in. |
| [Public IP addresses](public-ip.md) | Every public IP address and prefix: what uses it, which are paid for but unused or on the retired Basic SKU, whether DDoS Protection covers them, how much traffic they carry, who changed them, and whose an address is. |
| [Routing: what path does traffic take?](routing.md) | From one IP to another: where each address lives, the route each side picks, the next hop, whether the reply comes back the same way, and what every network security group on the way decides. |
| [Microsoft Sentinel operations](sentinel.md) | For the team that runs Sentinel: is it collecting what it should, are detections and automation running, is the incident queue being worked, what does it cost, and is Purview data arriving? |
| [Well-Architected Framework](well-architected.md) | A workload's gaps against the five pillars of the Azure Well-Architected Framework: Reliability, Security, Cost Optimization, Operational Excellence and Performance Efficiency. Each pillar combines Azure Advisor's recommendations with configuration checks read from Azure Resource Graph, so no workspace is needed; picking one adds the checks only logs can answer. The Assessment tab records the answers to the Well-Architected checklist and scores each pillar. |
